# DAC-3D 产品战略：视觉同步协处理器 V1.0

> 纲领文件。定义 DAC-3D 控制器从"实验室自用系统"走向"通用视觉检测控制设备"的
> 产品定位、生态关系、护城河与架构底线。写在写第一行产品化代码之前——**因为定位决定架构**。

---

## 0. 一句话定位

> **视觉同步协处理器（Vision Sync Co-Processor）**——坐在运动控制卡**旁边**，
> 把光学检测里"看"这件事做到运动卡做不到的**几十纳秒**精度；
> 一次只服务一套设备，可通过配方复用于不同检测系统。
> **不与运动控制卡竞争，而是做放大运动卡销量的增益力量**——如同 GPU 之于 CPU。

---

## 1. 核心类比：GPU : CPU ：= 视觉协处理器 : 运动控制卡

GPU 没有取代 CPU，它接管了 CPU 干不好的并行计算，反而让整机需求暴涨、CPU 卖得更多。
同一结构映射到本产品：

| | "CPU" = 运动控制卡 | "GPU" = DAC-3D 视觉同步协处理器 |
|---|---|---|
| 本职 | 多轴插补、轨迹、PLC 逻辑、安全 I/O、EtherCAT 主站 | 编码器触发的**纳秒级采集**、多相机/DMD/频闪融合、结构光图样、"用光定义曝光" |
| 干不好/不做 | 几十纳秒多光学器件同步、DMD 图样、视觉算法流水线 | 多轴运动闭环、PLC、安全链——**它压根不碰** |
| 共存关系 | 每台 DAC-3D 里都装着一块运动卡 | 坐在运动卡旁边，**吃它的编码器输出（PSO）** |
| 结合面 | ← 编码器位置流 / PSO 触发握手 → | 这就是两者之间的"PCIe" |

**关键：协处理器消费运动卡的输出，而不是替换它的运动环。** 分工线清晰——
这是"不竞争"能够成立的技术前提，也是下文架构底线的由来。

---

## 2. 为什么是真·双赢（增量飞轮）

有机制、不是口号：

1. 协处理器让以前做不了的**高精度光学检测应用**变得可行
2. 这些应用需要造整机 → 整机就得配一块运动卡
3. 更多整机 → 运动卡厂商多卖卡 + 光学元件多卖
4. 运动卡厂商的 TAM **被撑进它单独吃不下的高端视觉市场**
5. → 它有动力推荐/捆绑协处理器 → 更多协处理器 → 回到第 1 步

运动控制是成熟、价格战、正在商品化的市场；视觉同步是更新、更高毛利、尚无人定义的细分。
**本产品不进运动卡的红海抢食，而是把它的蛋糕做大的那股力量**——正如 NVIDIA 对 Intel 的早期关系。

---

## 3. 最易误读、也最关键的一点：护城河是"CUDA"，不是芯片

NVIDIA 真正的护城河**不是晶体管，是 CUDA + 开发者生态**。芯片能被任何代工厂流片；
CUDA 十几年沉淀的库、工具、习惯换不掉。

对本产品的直接含义——**FPGA 触发核是"硅"，是入场券，但不是护城河。**
一个像样的团队、甚至运动卡厂商自己，都能复刻"一块做快触发的 FPGA"。护城河必须建在软件层：

- **HAL + 配方生态**："随便接哪家相机/DMD/光源/运动卡都能跑"的集成层
- **算法库**：瑕疵检测、ARC 标定、CFAN、点云重建——别人重写要数年
- **SDK / 配方标准**：让集成商在其上开发，形成切换成本

> **silicon 让你能进场，software 让你留下。** 价值停在"快触发"会被商品化；停在"生态"才是 NVIDIA。

---

## 4. 诚实的风险（好战略要敢点名）

| 风险 | 说明 | 对策 |
|------|------|------|
| **被宿主吸收** | 运动卡厂商已有 PSO/飞拍，可能把纳秒视觉同步加进自家固件 | 差异化钉在它们结构上不会重投入之处：**DMD/结构光图样 + 多光学器件亚百纳秒融合 + 算法生态**，而非"快一点的触发" |
| **"双赢是一个阶段"** | NVIDIA 与 Intel 后来也成对手（Grace vs x86） | 一边深度共赢，一边攒够**独立软件价值**，不至纯粹仰人鼻息 |
| **商品化** | 只卖硬件盒必然价格战 | 盒子可薄利/开放，**利润与黏性放在 SDK/算法/配方** |
| **品类不存在** | 客户不知"视觉同步协处理器"为何物 | **主动定义并命名品类**（见第 5 节） |

---

## 5. 战略动作：创造品类，而非造"又一个控制器"

NVIDIA 不说"我做更快的图形卡"，而说"我发明了 GPU / 加速计算"。
本产品也不定位成"又一个控制卡"（那是往运动卡红海跳），而是：

> 开创并占据 **"视觉同步协处理器"** 这一新品类——运动卡是"CPU"，本产品是这一新品类的开创者。

**赢家往往是定义品类的人。**

---

## 6. 架构底线（战略对代码的硬约束）

战略不落到架构上就是空谈。以下四条为产品化代码的**不可让渡原则**：

### 6.1 ★ 运动卡/编码器输入 = 厂商无关的 HAL 边界（本次确认的首要约束）

- **不绑死 ZMC404。** 编码器位置流与触发握手抽象为统一接口（如 `IMotionFeedback` /
  `IEncoderSource`），ZMotion 只是其中一个驱动实现。
- 支持多种接入形态：**增量正交编码器（A/B/Z 差分）**、**运动卡数字位置（RS485/EtherCAT）**、
  **PSO/位置比较触发握手**——统一收敛到同一抽象，上层与 FPGA 逻辑不感知具体品牌。
- 新增一家运动卡厂商 = 写一个驱动 + 一份配方，**不改核心与 FPGA 逻辑**。
- **意义**：这是"增强所有运动卡厂家、生态中立"这句话在代码里的**兑现**。厂商中立不是
  PPT 承诺，而是 HAL 边界的结构性保证——只有输入厂商无关，双赢生态才可信。

```
     任一厂商运动卡 ── 编码器/位置/PSO ──►  ┌───────────────────────┐
     ZMotion / 固高 / 雷赛 / ...            │  IEncoderSource (HAL)  │  ← 厂商无关边界
                                            │   ├ ZMotionDriver      │
                                            │   ├ GugaoDriver        │
                                            │   └ EtherCATDriver ... │
                                            └───────────┬───────────┘
                                                        ▼
                                     FPGA 触发核 / 配方（对品牌无感知）
```

### 6.2 触发核永不碰运动
绝不重新实现插补/PLC/安全环。物理上保证"不竞争"，把运动域完整留给运动卡。

### 6.3 配方/SDK 层 = 公开、稳定、有文档的 API（你的"CUDA"）
从第一天按"给外部集成商用"的标准设计，而非内部脚本。护城河所在，投入优先压这里。

### 6.4 触发时序全部配方驱动、设备无关
换运动卡、换相机、换 DMD 只改配方与标定，不改逻辑。几十纳秒的时序参数
（ODELAY、脉宽、PSO 位置）全部写在配方里。

## 7. 待拍板的商业决策（影响投入侧重）

以下为需决策项，当前建议见"倾向"，最终由项目负责人定：

| 决策 | 选项 | 倾向 | 理由 |
|------|------|------|------|
| 护城河主层 | 软件生态 / 硬件性能 / 并重 | **软件生态** | 硬件是入场券易商品化；生态是 NVIDIA 式深护城河 |
| 厂商关系 | 多厂商中立 / 深绑一家 / 先自用 | **多厂商中立** | 议价权强、不绑一家生死；与 6.1 架构底线一致 |
| 产品化节奏 | 内部标杆先行 / 直接产品化 / 先验壁垒 | **内部标杆先行** | 用自家四项目跑通"一套控制器复用于不同系统"，本身即验证软件护城河与厂商中立 |

> 三个"倾向"其实是**同一条路的三个面**：先用自家光学/PCB/芯片/DMD 四项目把
> "一套控制器复用于不同检测系统"跑成真的，即同时验证了软件护城河与多厂商中立能力。

---

## 8. 一句话总结

> 把 DAC-3D 定位成**运动卡旁边的视觉同步协处理器**：不抢运动卡的活，而是靠几十纳秒
> 视觉同步 + 配方生态，让每一台高端检测机都愿意配一块运动卡——做生态里放大对方销量的
> 增益力量。硬件（FPGA 触发核）是入场券，**软件（HAL + 配方 + 算法生态）才是护城河**；
> 而"厂商无关的运动卡 HAL 边界"，是让"增强所有运动卡厂家"这句承诺在代码里成真的第一块基石。
