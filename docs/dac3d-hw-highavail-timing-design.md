# DAC-3D 通用单站视觉检测控制器 — 几十纳秒级时序 + 高可用设计 V1.1

> 本方案是 [`../Claude-DAC-3D产业化的软硬件架构设计-FPGA+运动控制卡.md`](../Claude-DAC-3D产业化的软硬件架构设计-FPGA+运动控制卡.md) 的升级篇。
> 现有架构解决了「单机 FPGA 自主触发 <10μs」；本方案在此基础上解决三件事：
>
> 1. **一套通用控制器**：同一台控制设备（硬件盒 + FPGA 固件 + 上位机软件）可复用到
>    实验室不同的视觉检测系统（光学元件 / 电路板 / 芯片 / DMD 细胞切割），
>    靠配置切换适配，无需为每套设备重写系统。
> 2. **几十纳秒级时序**：一套被控设备内部——XYZ 电机 / 相机 / 光源 / DMD 之间——
>    对齐到 **≤50 ns（目标 <20 ns）**。
> 3. **高可用**：单站级冗余与故障降级（双电源、看门狗、FPGA 自主运行）。

目标机型：图示 **DAC-3D Industrial** 整机（前面板 USB-C / RJ45 / 电源键，后面板 GX12×2 / SMA / HDMI / DB25 / C14，内部 ZMC404 + Zynq FPGA + 双电源 + DIN 导轨）。

---

## 定位说明（务必先读）

> **一台控制器 = 一套被控设备。** 本控制器在任一时刻**只控制一套**检测装置
> （一组 XYZ 电机 + 相机 + 光源 + DMD），**不做**多台设备同时控制、**不做**跨机站
> 联网同步。
>
> 它的「通用」体现在 **可移植、可复用**：这一台控制器搬到实验室另一套检测系统上，
> 接上那套的电机 / 相机 / 光源，改一份配方（recipe）即可投入使用——就像一把
> 「万能检测控制器」，一次装一套刀头。
>
> 因此本方案**不含**：主时钟单元、跨机 10MHz 参考分发、PTP 全站授时、Fleet 多机编排。
> 后面板 SMA 仅作**本机可选用途**：对外同步一台外部仪器、或从外部引入触发/参考做
> 特殊测量；平时不接。

## 0. 关键结论（先看这一页）

| 维度 | 现有 V1.0 | 本方案 V1.1 |
|------|-----------|-------------|
| 触发抖动 | <10 μs（软件往返级） | **<50 ns**（FPGA 硬边沿 + ODELAY 微调，目标 <20 ns） |
| 一套设备内多器件对齐（相机 / DMD / LED / Z） | 同一 FPGA，ns 级 | 保持 ns 级，各通道边沿可独立微调至 ~78 ps 步进 |
| 曝光时刻确定性 | 依赖相机内部快门 | **FPGA 门控照明频闪定义曝光**，绕开相机快门抖动 |
| 通用复用 | 单套系统一份软件 | **一套固件 + 配方（recipe）适配不同检测系统** |
| 供电 | 单/双电源 | **双电源 N+1 冗余，热备自动切换** |
| 主机/网络故障 | — | **FPGA 自主完成当前扫描（降级不停机）** |

核心工程判断：**"几十纳秒"不是靠把 FPGA 时钟从 100 MHz 提到更高就能拿到的**，
在单套设备内部靠三招叠加即可实现——
① 提升触发域时钟并用 ODELAY 微调边沿（压住生成粒度与通道偏斜），
② 触发全部由 FPGA 硬件直接产生（消除软件 10–50ms 抖动），
③ 用 **FPGA 门控照明频闪定义曝光**，绕开工业相机内部电子快门的抖动。

## 1. 时间误差预算（单套设备内）

要保证一套设备内器件间对齐 ≤50 ns，必须把误差逐项拆开、逐项压住：

| 误差来源 | 未处理量级 | 处理手段 | 处理后 |
|---------|-----------|---------|--------|
| FPGA 内部**触发生成粒度** | 1 拍 @100MHz = 10 ns | MMCM 生成 **250 MHz 触发域** = 4 ns | **<4 ns** |
| 各触发通道**边沿偏斜** | 布线/负载不等，数 ns | 每通道 **ODELAYE2**（~78 ps/tap）标定 | **<1 ns 残差** |
| 到各器件的**电缆传播** | 每米 ~5 ns | 等长线 + 每通道 `TRIG_DELAY` 标定 | **标定后 <1 ns** |
| 相机**曝光起点抖动** | 电子快门可达数十 ns~μs | **FPGA 门控 LED/激光频闪定义曝光** | **由频闪边沿决定，<50 ns** |
| DMD **图样切换抖动** | 依内部时序 | FPGA 触发其 TRIG_IN，边沿可 ODELAY 微调 | **<50 ns** |
| 时基本身的**相位抖动** | 板载晶振 ps 级 | 现有晶振足够（单机不需外部参考） | **<10 ps RMS** |
| **一套设备内合计（RSS）** | — | — | **≈ 15–40 ns（目标 ≤50 ns）** |

> 关键技巧：真正决定"这一帧采到了哪个瞬间"的，是**光**，不是相机内部计时。
> 让 FPGA 直接门控 LED / 激光频闪，相机开一个较宽曝光窗把频闪包进去——曝光的
> 有效时刻就由 FPGA 边沿决定，天然几十纳秒级。DMD 图样切换同理，用 FPGA 触发
> 其 TRIG_IN。**单机不依赖任何外部参考时钟**即可达标。

## 2. 单站时序架构（FPGA 为唯一时序主）

一套设备内的所有时序，全部由本机 Zynq 的 PL（FPGA 逻辑）在**同一个时钟域**里产生，
天然同源、无跨设备授时问题：

```
        ┌──────────────────────────────────────────────┐
        │              Zynq-7020  FPGA (PL)             │
        │   板载晶振 → MMCM → 250MHz 触发域(同一时钟源)  │
        │                     │                         │
        │   ┌─────────────────┴──────────────────┐      │
        │   │   PSO 位置比较（读 ZMC404 编码器）  │      │
        │   └───────┬────────────────────────────┘      │
        │           │ 到位即触发（同拍产生）             │
        │   ┌───────┴───────┬───────────┬───────────┐   │
        │   ▼ ODELAY_CH0    ▼ ODELAY_CH1 ▼ ODELAY_CH2│   │
        │ 相机触发×3       DMD TRIG      LED/激光频闪  │   │
        └───┼───────────────┼───────────┼─────────────┘  │
            ▼               ▼           ▼
     ┌───────────┐   ┌───────────┐  ┌───────────┐
     │ Basler ×3 │   │  DLP6500  │  │ 光源频闪   │  ← 同一 FPGA 边沿，
     │（硬触发） │   │（TRIG_IN）│  │（定义曝光）│    通道间 <1ns，
     └───────────┘   └───────────┘  └───────────┘    对齐 ≤50ns
```

- 因为**只有一套设备、只有一个 FPGA、只有一个时钟域**，不存在"两个时基要对齐"的问题——
  这正是几十纳秒在单机内最容易拿到的原因。
- XYZ 运动：XY 由 ZMC404 飞拍，编码器进 FPGA 做 PSO；Z（PI 压电）到位信号同样进 FPGA 参与时序。

## 3. ★ 单机 FPGA 升级（核心改动，落在现有 Verilog 上）

保留现有 `timing_ctrl.v / pso_generator.v / encoder_decoder.v / pwm_controller.v`，只加三处：

| 增强项 | 现状 | 改动 | 收益 |
|--------|------|------|------|
| 触发域时钟 | 100 MHz（10 ns） | MMCM 生成 250 MHz 触发域 | 边沿粒度 10→4 ns |
| 通道边沿微调 | 无 | 每触发通道例化 **ODELAYE2**（~78 ps/tap） | 通道间偏斜标定到亚 ns |
| 曝光定义 | 相机内部快门 | **FPGA 门控 LED/激光频闪** | 曝光时刻由 FPGA 边沿决定 |

新增/扩展寄存器（延续现有 0x00–0x3C 映射）：

| 地址 | 名称 | 描述 |
|------|------|------|
| 0x44 | ODELAY_CH0 | 相机触发边沿微调（tap，~78 ps/步） |
| 0x48 | ODELAY_CH1 | DMD 触发边沿微调 |
| 0x4C | ODELAY_CH2 | LED/激光频闪边沿微调 |
| 0x58 | STROBE_CFG | 频闪脉宽/极性/延迟（门控曝光参数） |

## 4. 整机硬件构成与接口映射（对应实物照片）

一台 DAC-3D Industrial 内部按**"控制 / 运动 / 电源"三区**布局在 DIN 导轨上：

| 区 | 组件 | 作用 |
|----|------|------|
| 控制区 | Zynq-7020 FPGA 板（PL 触发 + PS Linux） | 全部时序、TCP 控制服务、数据缓冲 |
| 运动区 | ZMC404 运动控制卡 | XY 飞拍、编码器输出给 FPGA、Z 轴协调 |
| 电源区 | **双 Meanwell 电源（N+1）** + ORing 均流 | 冗余供电，单电源故障不停机 |

**面板接口 → 功能映射**（与照片一一对应）：

| 接口 | 位置 | 功能 |
|------|------|------|
| **RJ45** | 前 | 以太网：上位机控制 + 三相机图像数据（GigE） |
| USB-C | 前 | 本地维护 / 配置 / 固件升级 |
| 3× LED | 前 | 电源 / 运行 / 故障 状态灯 |
| **DB25** | 后 | 多路 TTL/LVDS 触发总线（相机×3 / DMD TRIG / LED 频闪 / 备用） |
| **HDMI** | 后 | DMD（DLP6500）图样输入（DLP 走 DVI/HDMI 收图样） |
| **GX12 ×2** | 后 | 外部编码器 / 外部触发 / 安全联锁（航插，工业抗振） |
| **SMA** | 后 | **可选**：对外同步一台外部仪器，或从外部引入触发/参考做特殊测量（平时不接） |
| C14 | 后 | 市电输入 |

> 换一套被控设备时：接口不变，只是 DB25/HDMI/GX12 后面接的是新那套的相机/DMD/编码器，
> 上位机加载对应配方即可。

## 5. 高可用（单站级）

高可用 = **单站没有明显单点故障 + 故障后自动降级不停机**。三条链：

### 5.1 供电冗余（照片里已有两颗电源）
- 双电源经 **ORing（理想二极管 / LTC4370 均流）** 并联，任一故障另一颗全载接管，可热插拔更换。
- FPGA 监测每路电压/电流，异常点亮故障灯并上报上位机。

### 5.2 控制降级（FPGA 自主）
- **一次 START 之后，扫描由 FPGA 独立跑完**：即便上位机或网络掉线，Tier 触发逻辑自主执行
  （延续 V1.0 "触发逻辑由 FPGA 自主执行"哲学），数据先进 PS 端环形缓冲。
- 网络恢复后自动重连、补传缓存数据。

### 5.3 看门狗与健康遥测
- FPGA 硬件看门狗 + PS 端软件看门狗互监，异常自动安全停机（电机使能断开、光源关断）。
- 周期上报：温度、电压、时钟锁定、触发计数、错误码——上位机呈现，便于维护。

### 5.4 降级模式定义

| 故障 | 系统行为 | 影响 |
|------|---------|------|
| 一路电源坏 | 另一路接管，故障灯亮，告警 | 不停机 |
| 网络/上位机断 | FPGA 自主跑完当前批次，本地缓存 | 时序精度不变，恢复后补传 |
| 某相机坏 | HAL 热插拔，该通道降级/跳过并告警 | 其余器件不受影响 |
| 急停/联锁触发 | 立即断电机使能 + 关光源，进安全态 | 保护人和样品 |

## 6. 通用复用：一套平台适配不同检测系统

目标：**同一台控制器**（硬件 + 固件 + 上位机软件）搬到实验室任一视觉检测系统都能用，
一次只服务一套设备。靠三个支点，而不是靠给每套系统重写：

```
        ┌───────────────────────────────────────────┐
        │        通用控制器（硬件 + 固件 + 软件）      │  ← 只有一份，通用
        │   应用层 → 服务层 → 核心层 → HAL → FPGA     │
        └───────────────────┬───────────────────────┘
                            │ 加载不同【配方 recipe】
        ┌───────────┬───────┴───────┬───────────────┐
        ▼           ▼               ▼               ▼
   ┌────────┐  ┌────────┐      ┌────────┐      ┌────────┐
   │光学元件│  │电路板  │      │芯片    │      │DMD细胞 │  ← 一次接一套，
   │检测配方│  │检测配方│      │检测配方│      │切割配方│    换系统=换配方+接线
   └────────┘  └────────┘      └────────┘      └────────┘
```

1. **HAL 抽象已就位**：`IStage/ICamera/IDMD/ILight/IFPGA` 接口 + 驱动分离，
   接不同品牌/型号设备只改驱动层，上层逻辑不动（现有设计）。
2. **配方（Recipe）驱动**：每套检测系统 = 一份 YAML 配方（延续 `configs/recipes/wedge_filter.yaml`
   思路），声明这套用哪些设备、什么触发时序、什么算法流水线、什么合格判据。
   同一固件加载不同配方就变身不同检测机——**但始终只驱动当前这一套**。
3. **参数化时序**：几十纳秒的触发/频闪时序参数（ODELAY、脉宽、PSO 位置）全部写在配方里，
   换系统时按新设备标定一次即可，不改 FPGA 逻辑。

> 复用的收益：新检测系统上线 = 写一份配方 + 接线 + 标定，**不改核心代码**；
> 一套控制器在实验室里可以在不同项目间轮转复用；软件版本全实验室一致，便于统一升级维护。

## 7. 关键选型（相对 V1.0 的新增部分）

| 类别 | 组件 | 推荐型号 | 作用 |
|------|------|---------|------|
| 触发域时钟 | MMCM（FPGA 内） | Zynq-7020 内置 | 100→250 MHz 触发域 |
| 边沿微调 | ODELAYE2（FPGA 内） | Zynq-7020 内置 | ~78 ps/tap 通道偏斜标定 |
| 触发收发 | LVDS/TTL 驱动 | TI DS90LV / SN74 系列 | DB25 多路触发差分输出 |
| 频闪驱动 | 恒流 LED/激光驱动 | 按光源功率选 | FPGA 门控频闪定义曝光 |
| 供电冗余 | ORing 控制器 | ADI **LTC4370**（双路均流） | 双电源并联热备 |
| FPGA 主控 | SoC | Zynq-7020（沿用） | 全部时序 + 控制服务 |

> 成本量级：本方案相对 V1.0 的增量主要是 **ORing 供电冗余** + **频闪驱动电路**；
> 触发提速与边沿微调用的是 Zynq **片内资源**，基本零新增器件。

## 8. 实施路线

| 阶段 | 目标 | 交付/验收 |
|------|------|-----------|
| H-1 | 触发域提速 + 边沿微调 | 250MHz 触发域 + ODELAY，示波器测通道间偏斜 **<1 ns** |
| H-2 | FPGA 门控频闪 | LED/激光频闪由 FPGA 定义曝光，测有效曝光时刻抖动 **<50 ns** |
| H-3 | 一套设备内多器件对齐 | 相机触发×3 / DMD TRIG / LED 频闪同一基准，两两偏差 **≤50 ns（目标 <20 ns）** |
| H-4 | 双电源冗余 | 在线拔一路电源不停机 |
| H-5 | 配方复用验证 | 同固件加载 光学/PCB/芯片/DMD 四配方，各自接线后全部跑通 |

**验收金标准**：示波器同一基准，探同一台控制器输出的 **相机触发、DMD TRIG、LED 频闪**
三路上升沿，两两时间差 —— **≤50 ns 即达标，目标 <20 ns。**

## 9. 一句话总结

> 这是一台**通用单站视觉检测控制器**：一次只控一套设备（XYZ + 相机 + 光源 + DMD），
> 换套设备只换配方和接线。几十纳秒靠"**同一个 FPGA、同一个时钟域产生所有触发 + ODELAY
> 微调边沿 + 用光（频闪）定义曝光**"三招在单机内拿到，不需要任何外部参考或跨机同步；
> 高可用靠"双电源热备 + FPGA 自主降级 + 看门狗安全停机"守住单站可靠性。
