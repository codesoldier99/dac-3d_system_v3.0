# DAC-3D 高可用整机 + 几十纳秒级时间同步 硬件设计方案 V1.0

> 本方案是 [`../Claude-DAC-3D产业化的软硬件架构设计-FPGA+运动控制卡.md`](../Claude-DAC-3D产业化的软硬件架构设计-FPGA+运动控制卡.md) 的升级篇。
> 现有架构解决了「单机 FPGA 自主触发 <10μs」；本方案解决两件新事：
> **(1) 全实验室软件统一**（一套软件跑光学元件 / 电路板 / 芯片 / DMD 细胞切割多类项目）；
> **(2) 跨设备、跨机站的几十纳秒（≤50 ns）级统一时基与高可用架构。**

目标机型：图示 **DAC-3D Industrial** 整机（前面板 USB-C / RJ45 / 电源键，后面板 GX12×2 / SMA / HDMI / DB25 / C14，内部 ZMC404 + Zynq FPGA + 双电源 + DIN 导轨）。

## 范围说明（近期落地边界）

> **近期目标锁定「单机内、几十纳秒级多设备同步」**：一台 DAC-3D 内部的
> 3 台相机 / DMD / LED 频闪 / Z 轴之间，对齐到 ≤50 ns（目标 <20 ns）。
> 这条路径**不需要主时钟单元、不需要跨机 SMA 参考分发**，成本增量最小。
>
> 跨机站统一时基（第 2 节 Tier 2 主时钟、第 5.2 时钟冗余、第 6 节 Fleet 编排）
> 作为**可选的未来扩展层**保留；后面板 SMA 接口先作为升级预留（暂只用于本机
> SYNC 自检 / 未来接入参考）。下文 ★ 标记的小节为单机近期重点，其余为扩展层。
>
> 单机内部要拿到几十纳秒，靠的仍是三招（见第 1 节预算表）：
> **① 250MHz 触发域 + ODELAY 微调边沿；② 触发由 FPGA 直接产生；③ 用 FPGA
> 门控 LED/激光频闪定义曝光**——第 ① ③ 招在单机内即可完全实现。

## 0. 关键结论（先看这一页）

| 需求 | 现有 V1.0 | 本方案 V1.0 |
|------|-----------|-------------|
| 单机触发抖动 | <10 μs（软件往返级） | **<50 ns**（FPGA 硬边沿 + ODELAY 微调，实测目标 <20 ns） |
| 多设备对齐（3 相机 / DMD / LED / Z） | 同一 FPGA，ns 级 | 保持 ns 级，边沿可独立微调至 ~78 ps 步进 |
| **跨机站统一时基** | 无（各机独立） | **≤50 ns**（共享 10 MHz 参考 + 硬件触发骨干 + PTP） |
| 供电 | 单/双电源 | **N+1 冗余，热备自动切换** |
| 时钟主控 | 无 | **主/备主时钟单元，失锁自动切换 + 本地保持（holdover）** |
| 网络/主机故障 | — | **各机 FPGA 自主完成当前扫描（降级不停机）** |
| 软件 | 单机一套 | **一套固件，配方（recipe）差异化，Fleet 编排 N 台** |

核心工程判断：**"几十纳秒"不是靠把 FPGA 时钟从 100 MHz 提到更高就能拿到的**，而是三件事叠加——
① 全实验室共享一个物理参考时钟（消除频率漂移），
② 用 FPGA 直接产生并微调触发边沿（消除软件抖动），
③ 用 **FPGA 门控照明频闪定义曝光**，绕开工业相机内部电子快门的抖动。

## 1. 时间误差预算（Timing Budget）

要保证系统级 ≤50 ns，必须把误差逐项拆开、逐项压住。下表是分配预算：

| 误差来源 | 未处理量级 | 处理手段 | 处理后 |
|---------|-----------|---------|--------|
| 各机站时钟**频率**偏差 | 每机独立晶振，ppm 级漂移 → μs/s 累积 | 全站共享 10 MHz 参考，锁相 | **0 频率漂移** |
| 参考时钟**分发偏斜** | 电缆长度不等 | 等长同轴星形分发 + 抖动清理器 | **<3 ns** |
| 参考时钟**相位抖动** | — | LMK04828 / Si5340 抖动清理 | **<1 ps RMS** |
| FPGA 内部**触发生成** | 1 拍 @100MHz = 10 ns | 250 MHz PL 时钟 = 4 ns，ODELAY 微调 | **<4 ns + ~78 ps 步进** |
| 到各设备的**电缆传播** | 每米 ~5 ns | 等长线 + 每通道 TRIG_DELAY 标定 | **标定后 <1 ns 残差** |
| 设备**内部触发延迟** | 固定 + 抖动 | 固定量标定抵消；抖动靠选型 | 见下 |
| 相机曝光起点抖动 | 电子快门可达数十 ns~μs | **FPGA 门控 LED 频闪定义曝光** | **由频闪边沿决定，<50 ns** |
| **系统级合计（RSS）** | — | — | **≈ 20–40 ns（目标 ≤50 ns）** |

> 关键技巧：真正决定"这一帧到底采到了哪个瞬间"的，是**光**，不是相机的内部计时。让 FPGA 直接门控 LED / 激光频闪，相机开一个较宽的曝光窗把频闪包进去——曝光的有效时刻就由 FPGA 边沿决定，天然是几十纳秒级。DMD 图样切换同理，用 FPGA 触发其 TRIG_IN。

## 2. 三层时间同步体系（本方案的核心）

```
┌──────────────────────────────────────────────────────────────────────┐
│  Tier 1 · 实验室骨干网（时刻/协调）        载体: RJ45 以太网 + PTP     │
│  IEEE 1588 PTP 硬件时间戳，Grandmaster 下发 UTC 时刻                    │
│  精度: 数十 ns~亚μs   用途: 全站日志对齐、配方下发、慢协调、数据关联   │
├──────────────────────────────────────────────────────────────────────┤
│  Tier 2 · 物理参考时钟（频率/相位）        载体: SMA 同轴（后面板）    │
│  主时钟单元 MCU 下发 10 MHz + 1PPS，星形等长分发到每台 DAC-3D          │
│  精度: 亚 ns 抖动   用途: 全站锁同一频率，消除漂移，作为 FPGA 时基源   │
├──────────────────────────────────────────────────────────────────────┤
│  Tier 3 · 硬件触发骨干（事件/边沿）        载体: SMA / DB25 LVDS-TTL   │
│  主机 FPGA 广播 START/SYNC 及逐事件触发，从机 FPGA 锁相后同拍执行      │
│  精度: ≤50 ns（目标 <20 ns）   用途: 多机快门/图样/运动的严格对齐     │
└──────────────────────────────────────────────────────────────────────┘
```

- **Tier 1（PTP）** 给"这是几点几分几秒"——粗对齐、可路由、便于全站日志和数据关联。
- **Tier 2（10 MHz + PPS）** 给"大家用同一根节拍器"——一旦所有机站锁到同一物理参考，频率漂移直接归零，这是拿到几十纳秒的前提。
- **Tier 3（硬件触发）** 给"现在，一起动"——真正的事件边沿由 FPGA 在共享时基上产生。

> 若未来要做到**亚纳秒**跨机（例如瞬态飞秒项目），Tier 2/3 可升级为 **White Rabbit**（PTP + 同步以太网 + 相位测量，光纤，亚 ns），接口从 SMA 同轴改为 SFP 光口。当前"几十纳秒"用同轴方案即可，成本低得多。

### 2.1 拓扑：星形（推荐）与环形（高可用）

```
             ┌──────────────────────────┐
             │   主时钟单元 MCU (Master)  │  10MHz+PPS 源 / OCXO
             │   + 热备 MCU (Standby)     │  失锁自动切换
             └───────┬───────────┬───────┘
        SMA 等长同轴 │  星形分发  │
        ┌────────────┼───────────┼────────────┐
        ▼            ▼           ▼             ▼
   ┌─────────┐  ┌─────────┐ ┌─────────┐  ┌─────────┐
   │ DAC-3D  │  │ DAC-3D  │ │ DAC-3D  │  │ DAC-3D  │   每台 = 一个检测工站
   │  #1     │  │  #2     │ │  #3     │  │  #N     │   （光学/PCB/芯片/DMD）
   │ Zynq从机│  │ Zynq从机│ │ Zynq从机│  │ Zynq从机│
   └─────────┘  └─────────┘ └─────────┘  └─────────┘
        │            │           │             │
        └────────────┴─── PTP over 以太网 ─────┘  （Tier1，与时钟分开走）
```

- **星形**：分发偏斜最易控制（等长线），推荐默认。
- **环形/双星（可选高可用）**：主备两条独立时钟路径，任一断裂自动切换，用于产线不停机场景。

## 3. ★ 单机内部：从 10 ns 到亚纳秒边沿（近期重点）

在保留现有 `timing_ctrl.v / pso_generator.v / encoder_decoder.v` 逻辑的前提下，做三处增强：

| 增强项 | 现状 | 改动 | 收益 |
|--------|------|------|------|
| PL 时钟 | 100 MHz（10 ns） | MMCM 生成 250 MHz 触发域 | 边沿粒度 10→4 ns |
| 边沿微调 | 无 | 每触发通道加 **ODELAYE2**（~78 ps/tap） | 通道间偏斜可标定到亚 ns |
| 时基来源 | 板载晶振 | **外部 10 MHz 经抖动清理器锁相** | 跨机同频，抖动 <1 ps |
| 保持能力 | 无 | 从机内置 **TCXO/OCXO**，失锁进 holdover | 参考丢失时短时维持精度 |

新增/扩展寄存器（延续现有 0x00–0x3C 映射）：

| 地址 | 名称 | 描述 |
|------|------|------|
| 0x40 | REFCLK_STATUS | [0]:外部10M锁定 [1]:PPS有效 [2]:holdover [3]:主/备源 |
| 0x44 | ODELAY_CH0 | 相机触发边沿微调（tap，~78 ps/步） |
| 0x48 | ODELAY_CH1 | DMD 触发边沿微调 |
| 0x4C | ODELAY_CH2 | LED 频闪边沿微调 |
| 0x50 | SYNC_CTRL | [0]:主机模式 [1]:发SYNC [2]:收SYNC使能 |
| 0x54 | PTP_OFFSET | 本机 PTP 相对 Grandmaster 偏移（ns，只读） |

## 4. 整机硬件构成与接口映射（对应实物照片）

一台 DAC-3D Industrial 内部按**"控制 / 时钟 / 运动 / 电源"四区**布局在 DIN 导轨上：

| 区 | 组件 | 作用 |
|----|------|------|
| 控制区 | Zynq-7020 FPGA 板（PL 触发 + PS Linux） | 自主触发、PTP 从时钟、TCP 服务 |
| 时钟区 | **时钟/触发子板**（抖动清理器 + LVDS 收发 + OCXO） | 锁外部 10 MHz、收发 SYNC、holdover |
| 运动区 | ZMC404 运动控制卡 | XY 飞拍、编码器输出给 FPGA |
| 电源区 | **双 Meanwell 电源（N+1）** + ORing 二极管 | 冗余供电，单电源故障不停机 |

**后/前面板接口 → 功能映射**（与照片一一对应）：

| 接口 | 位置 | 功能 |
|------|------|------|
| **SMA** | 后 | **10 MHz 参考 / SYNC 触发 进出**（Tier 2/3 骨干，几十纳秒的命脉） |
| GX12 ×2 | 后 | 外部编码器 / 外触发 / 安全联锁（航插，工业抗振） |
| **HDMI** | 后 | **DMD（DLP6500）图样输入**（DLP 走 DVI/HDMI 收图样） |
| **DB25** | 后 | 多路 TTL/LVDS 触发总线（相机×3 / DMD TRIG / LED 频闪 / 备用） |
| **RJ45** | 前 | 以太网：PTP + 控制 + 图像数据（Tier 1） |
| USB-C | 前 | 本地维护 / 配置 / 固件升级 |
| 3× LED | 前 | 电源 / 时钟锁定 / 运行 状态灯（锁定灯=Tier2 已同步） |
| C14 | 后 | 市电输入（双电源共用或双路市电） |

## 5. 高可用（High-Availability）设计

高可用 = **没有单点故障 + 故障后自动降级不停机**。四条冗余链：

### 5.1 供电冗余（照片里已有两颗电源）
- 双电源经 **ORing（理想二极管 / LTC4370 均流）** 并联，任一故障另一颗全载接管，热插拔更换。
- FPGA 监测每路电压/电流，异常上报 Tier 1。

### 5.2 时钟冗余
- **主 + 热备两台主时钟单元**；从机检测参考丢失（REFCLK_STATUS 失锁）→ 自动切到备路。
- 切换瞬间从机进入 **holdover**（本地 OCXO 维持），几十纳秒精度可短时保持，切换无缝。

### 5.3 控制/网络降级
- **各机 FPGA 自主完成当前扫描**：即便上位机或网络掉线，Tier 3 已下发的 START 之后，触发逻辑由 FPGA 独立跑完（延续 V1.0 "触发逻辑由 FPGA 自主执行"哲学）。
- 网络恢复后自动重连、补传缓存数据（PS 端环形缓冲）。

### 5.4 看门狗与健康遥测
- FPGA 硬件看门狗 + PS 端软件看门狗互监。
- 每台机站周期上报：温度、电压、时钟锁定态、PTP 偏移、触发计数——Fleet 面板集中呈现，异常告警。

### 5.5 降级模式定义（明确"坏到什么程度还能干活"）

| 故障 | 系统行为 | 精度 |
|------|---------|------|
| 一路电源坏 | 另一路接管，告警 | 不变 |
| 主时钟坏 | 切热备 | 不变 |
| 主+备时钟全丢 | 各机 holdover 继续 | 短时几十 ns，随时间劣化，超阈报警 |
| 网络断 | 各机自主跑完当前批次，本地缓存 | 单机精度不变，跨机对齐暂停 |
| 某相机坏 | HAL 热插拔，该工站降级/跳过 | 其余不受影响 |

## 6. 软件统一：一套固件，跑遍全实验室

目标：光学元件、电路板、芯片、DMD 细胞切割——**同一套软件**，靠配置区分，而非各写一套。

```
┌─────────────────────────────────────────────────────────────┐
│  Lab Fleet Orchestrator（实验室编排层，中央一份）           │
│  · PTP Grandmaster（时刻源）   · 配方分发   · 集中遥测/告警  │
│  · N 台工站统一调度、批次追溯、报表                          │
└───────────────┬─────────────────────────────────────────────┘
                │ 以太网（PTP + gRPC/TCP）
   ┌────────────┼────────────┬────────────┐
   ▼            ▼            ▼            ▼
┌───────┐  ┌───────┐   ┌───────┐    ┌───────┐   每台跑【完全相同】固件
│工站#1 │  │工站#2 │   │工站#3 │    │工站#N │   差异仅在配方 recipe
│光学   │  │PCB    │   │芯片   │    │DMD切割│
└───────┘  └───────┘   └───────┘    └───────┘
   每台内部： 应用层 → 服务层 → 核心层 → HAL → FPGA（现有五层不变）
```

统一的三个支点：

1. **HAL 抽象已就位**：`IStage/ICamera/IDMD/ILight/IFPGA` 接口 + 驱动分离，换设备只改驱动层（现有设计）。
2. **配方（Recipe）驱动**：每类项目 = 一个 YAML 配方（延续 `configs/recipes/wedge_filter.yaml` 思路），声明启用哪些设备 + 算法流水线 + 触发时序参数。同一固件加载不同配方即变身不同检测机。
3. **时间同步服务内建**：每台 PS 端跑 `linuxptp`（Tier 1）+ FPGA 参考锁定管理（Tier 2/3），对上层透明。Fleet 层统一监控每台 PTP 偏移与时钟锁定态。

> 统一的收益：新项目上线 = 写一个配方 + 接对应硬件，不改核心代码；全站版本一致、可集中升级；跨工站数据天然同时基、可关联分析。

## 9. 一句话总结

> 把"参考时钟"和"事件触发"从各机各自为政，收拢成**全实验室一根节拍器（SMA 10MHz）+ 一条触发骨干（FPGA 广播）+ 一层时刻网（PTP）**；再用**双电源、主备时钟、FPGA 自主降级**堵住每一个单点；软件则靠 **HAL + 配方 + Fleet 编排** 做到一套固件通吃全实验室。几十纳秒不是靠更快的时钟堆出来的，是靠"大家共享同一个时基 + 边沿由硬件产生 + 用光定义曝光"三招合力拿到的。
